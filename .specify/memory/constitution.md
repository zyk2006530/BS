# 工程约束（规格驱动基线）

基线日期：2026-11-10（工程修订版增量；保留原任务证据）。适用范围：企业审批系统的后续设计、实现和验证。

## 1. 依据与变更顺序

权威依据为[工程修订版 PDF](<../../docs/midterm/中期设计文档-工程修订版.pdf>)，其 SHA-256 与用户指定原件一致：`938b113b1694c3a0146b83bb9da3be93af04ed6bffdc388c57bf48bba7b3ddab`。[原优化版仓库副本](<../../docs/midterm/中期设计文档-修订版.pdf>)仅作历史记录。工程化分解位于[规格目录](<../../specs/001-enterprise-approval/README.md>)。历史长稿不覆盖最新版；有冲突时先查 PDF，再修订规格、任务、测试，最后改代码。

## 2. 独立编码边界

PDF §5.2、§7.8、§9.2 要求自定义表单和流程模块由学生独立编码。模板配置、字段定义、动态录入、条件解释、实例生成及共用流程执行均属于此边界，不能以“通用引擎”名义绕开。不生成这部分业务实现、生成器、执行型伪代码或自动代码补丁。允许整理需求、静态原型、技术边界和黑盒验收清单；学生保留独立实现的阶段提交与测试证据。

## 3. 权限优先

每次查询、写入和重放都核验当前身份、账户限制及访问能力。系统管理员没有隐含业务正文、附件、审批或统计权；统计聚合权不等于正文权。草稿仅本人可读。不得靠隐藏按钮替代后端鉴权，不得把越权对象泄露为日志、票据预警或分页计数。

## 4. 冻结与不可变历史

提交时冻结金额、部门、模板/策略版本、路径和实际人员。已发布定义只追加；启用模板下旧发布版草稿可提交，停用仅阻止新提交。驳回、撤回后新建关联草稿；换版复制填写并确认，不静默迁移或改写原单。审批及审计记录只追加，业务数据库账号不得更新或删除。

## 5. 并发与原子性

申请写入以预期版本及 UUID 请求键防重；同键同指纹重放成功结果，同键不同目标或内容冲突。事务内锁申请后、检查版本前复查幂等结果；交接先配置锁和权限再查成功结果，最后检查双版本。锁顺序固定 `system_config → user（ID升序）→ auth_session → application（ID升序）→ file_object（ID升序）→ inbox_state（user_id升序）`，跳过不需要的层，不得逆序补锁。普通流转不回取配置锁，不锁全体用户；缺失收件箱由独立事务修复。普通业务写在申请锁后基于当前已提交权限重验账户、节点和动作，撤权不追溯已通过检查的在途请求。数据库锁等待上限3秒，死锁或等待超时整事务回滚，返回503及 `retryable=true`，用户确认后复用原请求键；409需刷新确认，不自动重放。业务、日志、通知、邮件任务及成功请求结果同事务提交；文件字节传输、散列和 SMTP 不持上述数据库锁。交接同时递增分配和申请版本，WAITING节点不提前计时。

## 6. 安全与数值契约

使用持久、可撤销的不透明随机会话及数据库摘要，不使用 JWT。Web Cookie+Origin+CSRF 与原生 Bearer 互斥；原生匿名入口不收 Cookie、不设置 Cookie。ID/版本和金额经 JSON 传递为字符串；计算使用 BigDecimal，拒绝超精度而非截断。文件存私有卷，按当前业务权限读取。密码、令牌、SMTP 凭据不入库明文、不入日志、不入仓库。

## 7. 单体与范围控制

保持 Spring Boot 3 单体 + MySQL 8 + Vue 3/TypeScript + uni-app 小程序。前台轮询摘要、后台持久任务，不引入 WebSocket、Redis、工作流平台、OCR、会签、委托或自动审批来扩大范围。所有新增依赖明确版本、用途及许可；部署镜像、包管理器锁文件在工程阶段固定。

## 8. 证据不等于计划

PDF 中 T01—T22 是待执行验收，不是已通过的测试。完成任务须有代码、对应测试、真实环境及证据；规格检查、原型图、开发者工具与真机测试分别记录，不相互替代。MySQL 锁/约束/回滚必须在独立 MySQL 环境测，性能目标必须实际压测。不得为演示修改生产时钟、绕过鉴权或缩小性能数据量后冒称达标。

## 9. 保护现有工作

仓库已有设计稿、原型和 PDF 的未提交修改；按最小范围增量更新，不清理或重置他人改动，不自动提交或推送。部署数据、上传文件、密钥、缓存与本地环境配置排除在版本控制之外。
