# TASK-06/07/08 验证记录

## 范围与边界

本轮依据工程修订版规格实现私有附件、固定采购、差旅和报销的后端业务校验。没有实现提交编号、正式行映射、流程实例、审批动作、模板解释器或两端业务界面；TASK-09/10 保持学生独立编码，T01—T22 不因局部检查通过而自动升级。

实现与接口见[附件协议](<private-files-api.md>)、[固定业务校验契约](<fixed-business-validation-api.md>)。当前完整校验接口只检查本人已保存草稿并生成候选快照，不会冻结持久历史或改变申请版本。学生提交内核必须在其事务和锁序下重查版本、权限、附件健康及关联源，再自行写入正式行与不可变快照。

## 环境与可复现命令

- Windows 主机，Azul Zulu Java 17.0.17+10、Maven 3.9.11、Spring Boot 3.5.7；JVM 使用 Asia/Shanghai，数据库业务连接 UTC。
- Docker 隔离 MySQL 8.4.7，固定镜像 digest 见[原始结果](<../../backend/evidence/task060708-mysql.json>)。每次创建随机容器、随机凭据，迁移账号与业务账号分离。HTTP 进程使用 `approval_app`，日志和凭据不写入证据。
- 每次脚本先复制构建包为独立临时 JAR，再核对包内 V1—V5 SQL 与源码一致，避免后续构建改写正在测的包。私有文件卷为独立临时目录，测试结束清理，不连接现有开发数据库。

```powershell
. ./scripts/use-java.ps1
./backend/mvnw.cmd -f backend/pom.xml spotless:apply verify -B
python scripts/verify_task060708_mysql.py
python -m unittest discover -s tests -p "test_*.py" -v

```

为运行六项真实 Java 健康探针测试，另设置 `DEPLOY_JAVA_HOME` 指向本机 JDK；这些测试不代替 Docker 业务验证。业务验证脚本不隐式重新构建，先运行 Maven。

## 已验证内容

| 区域 | 操作与断言 |
|---|---|
| 文件校验与私有访问 | JPG/PNG/PDF 文件头夹具；扩展名/MIME/头不一致、目录穿越名称、额外 part、超过 10 MiB 拒绝；超过 1 MiB 的合法上传不误走 JSON 限制；字符串字节数和 SHA-256 一致；匿名、他人、纯管理员无权读取；PDF 强制下载，响应 no-store/nosniff |
| 绑定与并发 | 申请版本递增；UUID 成功原键重放不递增；异内容键冲突；同对象或同字节跨用途整单去重；四个并发重试只产生一条绑定和一次版本递增；已绑定文件必须带有权申请上下文 |
| 生命周期 | 解绑入持久队列，先 DELETING 后删盘再 DELETED；一对象绑定两单时移除一单不误删；缺失字节标 DAMAGED 并保留历史绑定、拒新绑定；末次解绑缺字节仍完成清理；领取与失败重试用单测补充 |
| 崩溃状态恢复 | 隔离 SQL/磁盘夹具模拟过期上传临时字节、改名后未 READY、DELETING 已缺字节、25 小时未绑定 READY 及旧孤儿；重启后回收完成，仍有效 15 分钟上传租约不被抢走 |
| 采购 | 两行 `1.005 × 5.00 → 5.03`、`1.004 × 5.00 → 5.02`，加运费 1.00 为 11.05；两报价闭合；超精度、预算不足、选中报价差额、缺依据、单一来源及非最低价理由检查；ONLINE 必须链接和图片，服务端不抓取外部链接 |
| 差旅 | UTC-Z 完整时间；北京时间跨午夜、同日、跨月自然日；倒置时间拒绝；OTHER 交通方式需要解释；预算非负，阈值路径不在本模块执行 |
| 报销 | 三费用汇总、多票/逐票号码；缺票拒绝；整行无票说明与已绑定票据互斥；独立报销说明必填；关联仅本人已通过采购/差旅，不扣减原预算，重复关联可行 |
| 关联冻结接口 | 初始不存在学生 `flow_instance` 时安全 503；随后仅在隔离测试库创建最小只读来源夹具并给业务账号 SELECT，验证地点日期预算/采购项目预计金额摘要和原单元数据；未生成生产表或任何流程执行代码 |
| 持久限流 | 账户每分钟 30 次上传尝试，拒绝的格式也计数；第 31 次返回 429 与 Retry-After，计数可从 MySQL 核对 |

恢复检查明确使用可重建的中断状态夹具，不声称完成生产电源故障、真实进程强杀各微秒窗口或磁盘拔出测试。文件头校验不声称杀毒、完整图片解码或 PDF 安全审计。

## 构建结果与取证

最终构建已通过 **172 项 Java/HTTP 测试**，零失败、错误、跳过，Spotless 与 Checkstyle 均通过；独立 Python/部署/真实 JDK 探针回归 **71/71**，规格一致性检查通过。

最终隔离 MySQL/HTTP **14/14 组通过**，152 次 HTTP、84 次成功信封核对、2 次应用启动。真实未完成 TCP multipart 在 **120.08 秒**返回 `408 UPLOAD_TIMEOUT`，且未产生 READY 对象；没有缩短客户端超时来伪造业务截止。受测 JAR SHA-256 为 `f6d70e742ff89194479aae2088e81f93765ca9a85be34d57435c1a3fd28daea0`，迁移摘要、镜像和逐组耗时见[机器证据](<../../backend/evidence/task060708-mysql.json>)。

真实网络检查曾发现默认容器路径在 60.06 秒返回 401，早于应用截止；补丁关闭 Boot 自动 multipart 注册并设置 Tomcat 独立上传读取超时 125 秒，保留应用 120 秒硬截止，不放开错误路径权限。新增三个配置回归测试，整轮重新构建和真实数据库验证均通过。

独立校验器、部署静态配置回归已通过。固定 digest Nginx 的 `nginx -t` 已实际通过，上传路径单独 11 MiB、关闭请求缓冲、125 秒代理收发超时；其他 JSON 保留 1 MiB。镜像锁定远端摘要三项复核通过。未重新启动完整 Compose，也不据此声明生产 HTTPS/真机/整体恢复验收通过。
