## 执行条件与证据规则

### 测试层与数据

- **U（单元）**：金额逐行舍入、阈值、自然日、授权判定、指纹与摘要等纯逻辑。模拟对象不能证明数据库约束和并发正确。
- **I（集成）**：实际服务及独立的 MySQL 8/InnoDB 测试库，执行真实迁移、外键、唯一约束、行锁、事务、任务恢复。禁止以 H2、SQLite、内存仓库或全部 mock 代替这一层。
- **E（端到端）**：通过部署后的桌面页面和真实 HTTP 接口办理，保留经脱敏的网络证据；直接构造请求验证按钮以外的权限边界。
- **M（移动）**：微信开发者工具加至少一台 Android、一台 iOS 真机；H5 和关闭合法域名校验的工具演示不能代替真机验收。
- **O（运维）**：空环境构建、部署、重复初始化、重启、成组备份与恢复。

数据覆盖研发、市场、财务三个部门；员工、部门负责人、财务审批人、企业负责人、系统管理员五类角色；跨部门指定人员、无额外授权管理员、待确认、已拒绝、已停用和强制改密账户。固定流程配置财务与企业主备、部门备选；至少两个启用管理员。记录每个测试账号当时的角色、部门、节点及显式授权，不使用真实个人票据或生产数据。

基础单据包含两行采购、两家报价，三行报销且一行无票、同一费用行多张票，同日和跨月差旅，旧发布版设备借用草稿、运行中及各终态实例。每个竞争子例使用独立单据，记录初始化摘要，避免前一子例终态污染后续判断。

### 证据最低集合

每例记录：构建提交/标签、迁移版本、测试时间、环境、账号权限、测试数据标识、操作与输入、预期、实际、结论和缺陷编号。HTTP 证据保留方法、资源、脱敏请求与响应、状态码、`requestId`、版本和请求键关联，不保存原始密码、会话令牌、Cookie、CSRF 或 SMTP 密钥。数据库证据用独立只读核查账号导出本例相关行与计数；不授予业务账号额外写权限来方便测试。截图和录屏不能替代响应与数据库对账。

并发使用两个独立连接/客户端，用屏障同时放行已准备请求；记录开始与完成时间、提交顺序、结果及数据库前后快照。故障注入只在隔离测试环境启用，并记录注入点、回滚和恢复过程。测试时钟只存在于测试环境；不得改生产时钟、删去授权或跳过截止规则来制造演示结果。

## T01—T22 验收用例

## T01 身份

- **测试层**：U、I、E、M。
- **前置条件**：有启用部门、已存在的规范化用户名和邮箱、管理员及未确认账户；前后端均可采集字段错误。
- **操作/输入**：注册有效账户；分别提交用户名长度 3/4/64/65、大小写及首尾空格重复、规范化邮箱重复、密码 7/8/64/65 个 Unicode 字符；并发注册相同规范值。添加伪造 `role`、确认部门或用户 ID。待确认时直接调用申请和任务接口；管理员确认部门后重新获取权限再提交。姓名与邮箱另测 1—80、最长 254 字符的边界。
- **可判定预期**：有效注册为 PENDING，不取得管理或业务办理权；重复、非法格式与越界被拒绝且前后端对应字段一致；并发唯一性不产生两个账号。角色及确认部门只能由服务端确认流程决定。确认后才开放业务，注册部门接口仅返回启用部门 ID 与名称。
- **证据要求**：字段错误、并发响应、规范值唯一行、账户状态与确认审计、确认前后业务请求。
- **状态**：`NOT_RUN`。

## T02 授权

- **测试层**：U、I、E。
- **前置条件**：本人和他人草稿、本部门及跨部门已提交单、WAITING/PENDING/已处理节点人员；正文及统计分别授权，含无额外授权管理员。
- **操作/输入**：逐身份直接请求列表、详情、审批、文件预览下载、统计及钻取，篡改申请、部门、用户、文件和绑定 ID。只授统计后请求正文；只授正文后请求审批。运行中以后续 WAITING 人员读取，再终结流程以未处理人员和已处理人员重读；撤销或到期独立授权后重试通知跳转。
- **可判定预期**：他人草稿永不可见；管理员身份本身不放行业务正文或审批；列表先过滤再分页计数。审批中各已分配节点人员可阅读必要材料，但只有当前节点可动作；终态取消未处理人员的节点阅读来源，保留已处理人员及申请人历史读取权，独立部门或显式授权另算。不可见或不存在资源均 404；有阅读权但禁止动作 403。统计不授正文、附件或审批权。
- **证据要求**：身份×资源×动作响应表、权限/授权快照、分页 total 对账、正文/附件与通知跳转网络记录。
- **状态**：`NOT_RUN`。

## 关键边界的可执行测试步骤

以下为测试驱动步骤，不是业务实现。执行前从实际接口取得最新版本、独立 UUID 请求键与合法测试会话。HTTP 路径均加 `/api/v1`；每个子例完成后只清理隔离测试库，不操作生产。

### C1 同版本竞争（T08）

1. 创建并提交至少两节点单据，确认第一节点 PENDING、申请版本 V；记录所有相关表的初始行数。
2. 两客户端读取 V，准备 `POST /tasks/{taskId}/approve`，正文均含 `expectedVersion: V`、不同请求键；屏障放行。
3. 断言一方 200、一方 409；数据库申请版本为 V+1，第一节点通过、恰有一个下一待办，批准记录一次，接收人事件唯一，不重复邮件/请求结果。
4. 使用新单据，审批人与申请人分别准备批准/撤回，二者读同一 V。先阻塞撤回至批准提交再放行，断言撤回 409，即便申请仍审批中；再用新单据反向阻塞，断言撤回成功后批准 409。
5. 新单据屏障同时放行批准/撤回，核对最终路径符合唯一胜者，禁止两项动作都生效。

### C2 响应丢失、锁内重查及重放（T09）

1. 对创建草稿、删除草稿、批准和节点交接各执行一次：保存请求方法/路径/目标/动作/规范正文/请求键；让事务成功提交但客户端收不到响应。
2. 不改任何请求字段，重发原键，比较原成功结果与持久请求记录；断言无第二次业务写。创建返回同 ID；删除在目标已不存在时仍返回原 204；交接沿用原 expectedConfigVersion 也返回原成功结果，不再次递增分配/配置/申请版本。
3. 同键改目标、改意见或改规范路径，断言 409且无写入；不同键携旧版本断言409。另一操作人使用该键不取得原操作人结果。
4. 两连接并发同键创建，断言只有一草稿/请求记录。批准并发同键时让第二请求在申请锁外查不到记录并等待，第一提交后第二取得锁，断言锁内重查读到结果而非旧版本409。
5. 撤销已有资源访问权或停用账户后重试，断言当前认证/授权先约束重放；普通管理写不同于节点交接，不承诺按键自动重放。
6. 在写业务后、写成功结果前注入数据库异常，确认全部回滚；恢复服务复用同键应可成功一次，不把失败结果永久缓存。

### C3 绑定与物理清理竞争（T11）

1. 两单合法共享同一 file_object。解绑 A 并执行清理，断言 B 可下载且字节摘要未变。
2. 在解绑事务提交前注入失败，断言 A 绑定仍存在、无生效清理任务，原字节可读。
3. 构造无引用对象；连接一持文件行锁准备标记清理，连接二尝试复制/新绑定，屏障控制两种提交先后。
4. 绑定先提交时清理复查引用并保留文件；清理先标记时新绑定被拒绝，不得绑定到已删除/清理中对象。确认任一结果均无有效绑定指向丢失文件。
5. 制造物理删除失败并重启清理器，恢复后重试完成；超过24小时未绑定READY入清理，有引用不删除。锁内DELETING提交后才删两条路径并回写DELETED，已无字节视为成功；DELETING禁新绑。
6. 用可控时钟使15分钟UPLOADING租约到期，分别在上传中及原子改名后中断，恢复只清理不可复活READY；上传超过2分钟停止。每日核对发现24小时无元数据对象复查清理，READY损坏告警/拒绑但保留绑定。

### C4 通知顺序、快照和待办摘要（T12）

1. 选两个接收人 U1<U2，构造两笔流转的接收人业务顺序相反；两个客户端同步执行，核验都按 U1→U2 持锁，无因业务顺序导致的锁环。可重试数据库错误不得造成部分业务或重复通知。
2. 对四类事件重复发起请求及重启服务；逐接收人检查 `(recipient_id,event_key)` 唯一、delivery_seq 递增且无回滚事务消息曝光；站内列表持久可查。
3. Web与小程序均打开未读页；Web单条已读，观察小程序下一摘要后更新未读数和通知页。重复已读不再递增revision。
4. 保持待办数量不变，用另一样本替换一个任务，或让同任务交接/申请版本变化，记录前后 taskDigest；即使 inboxRevision 不变，下一同步仍更新摘要并刷新待办。详情独立比较申请版本，不以未读数代替版本。
5. 并发插入通知与已读时读取摘要，核对同一只读可重复读快照内的 revision、last_delivery_seq、未读数及任务摘要，不接受拼接多个时间点的响应。

### C5 全部已读边界（T12）

1. 用户U打开通知页取得签名 readBoundary，记录 B、到期时间及当时未读集合。
2. 新消息在该边界之后提交，序号为 B+1；再发 `POST /notifications/read-all`，只提交原 boundary，不由客户端指定其他用户或放大B。
3. 断言仅U的≤B未读消息改变、B+1仍未读；其他用户不变。重复原 boundary，断言无额外已读变化及revision增长；无需当前revision仍等于打开时值。
4. 让新消息与全部已读屏障竞争，两种锁先后都不得误读>B消息；新通知顺序应来自inbox_state锁，不以全局自增ID或请求开始时间猜测。
5. 令测试时钟超出发放后15分钟，原边界返回409并要求刷新确认。篡改签名、换用户或伪造B必须拒绝且不写数据；记录实际错误，不把PDF未指定的细分错误码冒充既定契约。

### C6 邮件的租约与至少一次（T12）

1. 在通知/邮件任务事务提交前暂停，确认消费者不能发送未提交邮件；回滚后无站内通知与邮件任务。
2. 提交成功后领取邮件，记录租约，在发送前终止消费者；到期恢复并重领，断言可最终投递。
3. SMTP发送成功但保存结果前中断，恢复后允许再次发送；按任务关联核实站内通知仍只有一次，不要求SMTP恰好一次。
4. 令SMTP持续失败，用测试时钟验证1、5、30分钟重试间隔，失败状态持久且错误脱敏；站内通知与审批不回滚。邮件仅含编号、状态、登录入口，不附正文与票据。

### C7 催办与审批/交接（T17）

1. 激活节点，冻结默认24小时，记录 due_at 和 assignmentVersion A；等待节点无截止计时。
2. 测试时钟置截止前一瞬扫描，计数为0；置到截止并扫描，最迟截止后一分钟内产生一条 `(node,A,TIMEOUT)` 催办及对应通知/邮件；重复扫描、双执行器和重启都不增加同分配记录。
3. 分别对批准、驳回、撤回、交接设屏障，使业务动作先提交再放扫描；扫描重验后不对旧分配新增催办。
4. 用新样本使催办先提交后业务完成，允许历史催办保留，但跳转显示最新状态；交接后A+1重新计时，仅新到期后可产生新分配催办。
5. 全程核对申请版本只随业务动作变化，催办不改变状态、版本、已办及审批人；无无权主管邮件。

### C8 管理全局版本与人员停用（T18）

1. 管理员A/B读取同一configVersion C，分别准备两项不同管理变更，屏障放行；断言仅一项成功并令C+1，另一409后必须刷新和再次确认。
2. 仅剩两名启用管理员时互相撤销，以配置锁串行，断言不能两次成功导致无人可用。
3. 用测试连接暂持配置锁，令A的管理请求已通过锁前认证而等待；在受控锁交接中先提交撤销A管理员/停用A，再让A取得锁。断言锁内重读拒绝，目标、版本与审计不被A改变。
4. 人员有负责人、有效配置主备、WAITING/PENDING引用时直接停用，断言拒绝并列出交接事项。分别完成继任、替代配置发布、实例交接后再停用。
5. 对提交解析与停用放屏障：提交先取得配置锁时，要么先形成有效快照使停用重新检查引用并拒绝，要么完成必要交接后停用；停用先完成时，后续提交不得引用失效人员、不得静默用备选掩盖无效配置。

### C9 会话、Web/原生隔离及攻击输入（T21）

1. HTTPS Web登录前取CSRF上下文，缺失/错误CSRF、非白名单Origin分别调用登录/注册/退出和草稿写入，断言拒绝且状态不变；成功登录轮换上下文。查sid为Path=/、无Domain、HttpOnly/Secure/SameSite=Lax，不在响应体泄露Web令牌。
2. 无Cookie调用原生登录，仅返回Bearer会话且不设置Cookie；携Cookie调用原生匿名入口、携sid与Bearer调用已认证接口均拒绝。单纯User-Agent/clientType变化不能绕过CSRF。
3. 查看数据库只有32字节随机令牌的SHA-256摘要；用测试时钟分别达到空闲30分钟、绝对7天，调用接口为401。持续访问只更新last_seen_at，不能延长绝对截止。退出撤销当前会话，改密/重置/停用撤销全部；强制改密账户不能办理业务。
4. 将纯文本字段填入脚本与HTML、关键词填SQL元字符及`%`/`_`、原文件名含`../`及绝对路径；确认无脚本执行、无SQL扩权和路径逃逸，错误不返回SQL/堆栈/磁盘路径。直接访问私有卷URL应不可用；检查CSP、nosniff、安全Content-Disposition及no-store。
5. 隔离窗口内测试同IP第21次登录、第11次注册、同规范化账号第6次失败登录（15分钟内）、同账号第31次上传（1分钟内），越限429并有Retry-After；用并发和重启验证MySQL计数。测试已存在与不存在账号统一凭据错误及同类哈希处理；不得仅靠脆弱时间差断言不可枚举。伪造公网转发地址不能绕过限流。
6. 核验Argon2id参数为19,456 KiB内存、2次迭代、并行度1、16字节盐、32字节摘要；Unicode密码不裁剪/规范化/截断。检查凭据不入任何日志、数据库不存明文密码或令牌。JSON超1 MiB、服务不可用和事务重试耗尽分别核验413、503与retryable，避免把服务错误伪装参数错误。
