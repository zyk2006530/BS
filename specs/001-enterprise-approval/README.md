# 001 企业审批系统：规格入口

状态：`SPEC_BASELINE`，不是业务实现完成。基线建立于 2026-11-09。

## 依据与优先级

1. 用户指定的优化版 PDF；仓库内[修订版 PDF](<../../docs/midterm/中期设计文档-修订版.pdf>)是字节一致的可追踪副本，SHA-256：`92c65833438b707a2f5acb66ff58832ceb780f033e9819983dd15fcafa5e4182`。
2. [工程约束](<../../.specify/memory/constitution.md>)，尤其独立编码、权限、冻结历史与证据边界。
3. 本目录的工程化规格；若与 PDF 冲突，应先修正规格，不以实现方便推翻设计。

[旧版长稿](<../../docs/设计文档.md>)仅供历史检索。[报告源文件](<../../docs/midterm/report.typ>)可用于定位和重建，但重新编译出的 PDF 不能自动取代本基线；需要人工审阅并更新摘要。

## 开始一个任务

- 先读关联需求及 PDF 章节，确认任务依赖已完成，不能把“文档写好了”当作前序业务实现完成。
- 在任务中写清拟修改目录、异常路径和对应 T 编号；实现采用测试先行或同步编写测试。
- 涉及自定义表单/流程执行的任务由学生本人完成；AI 只处理规格与非执行型验收说明。
- 实现后使用对应环境执行验证，保存构建标识、输入、响应、数据库核对和证据，再更新任务和测试状态。
- 同步修改[任务文档](<tasks.md>)与[机器清单](<manifest.json>)，运行[检查器](<../../scripts/verify_specs.py>)及其[单元测试](<../../tests/test_verify_specs.py>)。

## 当前状态与检查范围

已完成的是规格基线和检查工具。所有业务实施任务仍为 `planned`，T01—T22 为 `NOT_RUN`；未建立业务源码、运行环境、Compose 或业务 CI。完成的 `TASK-00` 不代表采购闭环、移动端、性能或备份恢复可用。

检查器只保证本轮受管文档的 PDF 指纹、编号覆盖、依赖无环、状态、证据路径和本地链接一致，不证明规格内容全面正确，更不执行业务验收。它不会递归校验历史材料中的仓库外课件或旧交付链接。通过 `--source-pdf` 可以额外核对用户指定的外部原件；不指定时只核对仓库副本，便于克隆后运行。

变更 PDF 需要人工确认设计变更、同步所有受影响需求/任务/验收，重新计算摘要并复跑检查；不能仅修改摘要消除错误。
