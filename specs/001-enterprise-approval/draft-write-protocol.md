# 草稿公共写协议

TASK-05 后端采用申请行版本与成功请求记录。Web 和小程序在 TASK-13/14 集成此协议；本次不包含两端业务页面。

## 请求与返回

统一前缀 `/api/v1`。创建为 `POST /applications`，正文仅 `type` 及可选 `templateVersionId`、`sourceApplicationId`。当前可创建 PURCHASE、TRAVEL、REIMBURSEMENT；CUSTOM 和正式源单复制返回明确的 503 不可用错误，不创建半成品。

读取为 `GET /applications/{id}` 和 `GET /applications`。列表接受 `view=mine|authorized`、`type`、`status`、`submittedFrom`、`submittedTo`、`keyword`、`departmentId`、`page`、`pageSize`；先应用当前授权，再计数及分页。关键词中的 `%`、`_` 按字面匹配标题或编号。时间边界为包含起点、不包含终点。正文授权不来自 SYS_ADMIN、FINANCE_APPROVER 或 STATISTICS；他人草稿始终不可读。

保存为 `PUT /applications/{id}/draft`，正文为 `expectedVersion`、`title`、`remark`、`payload`。删除为 `DELETE /applications/{id}`，JSON 正文仅 `expectedVersion`。创建返回 201，保存返回 200 和新 `rowVersion`，删除返回 204。除 204 外成功响应使用 `data`、`requestId`、`serverTime` 封装。ID、外键、版本及金额使用字符串，非空金额固定两位；不得把 ID 转成 JavaScript Number。

每次申请写操作都携带 UUID `Idempotency-Key`。键在发请求前生成，直到结果确定之前不得更换。服务端指纹包括方法、规范路径及目标、动作、递归排序对象键后的完整 JSON；数组顺序保留。未知字段、数字型 ID、超范围版本、非法类型及服务端只读字段返回 400。相同操作者、动作、键且指纹相同才可重放；异目标或异内容返回 409。失败不持久化为成功记录。

服务端先验当前身份及现存访问权限。既有申请写先锁申请，再重验当前账户、会话、本人草稿和动作，查成功记录后才验版本。创建的唯一键竞争败者先回滚新草稿，再在新事务读取胜者。删除完成后，原操作者原键原指纹可再次得到 204；其他键不能据历史记录恢复已删除草稿。

## 两端每单写队列

每个客户端按申请 ID 建立单独队列。保存、绑定、解绑及删除必须进入同一队列，不允许自动保存与上传完成回调并行消耗同一个版本。不同申请可并行；服务端版本检查仍是跨设备竞争的最终约束。

1. 队首取最近一次已确认的 `rowVersion`，构造不可变正文并分配 UUID 键，持久保存这次待确认请求。
2. 发送期间允许用户继续本地编辑，但不修改在途正文，也不复用其键发送新内容。
3. 成功后用响应的新版本推进队列，合并附件绑定列表；只有确认删除成功才移除本地草稿。
4. 网络中断、响应丢失或可重试 503 时保留原方法、路径、键和原始正文，恢复后重试同一次请求。不得把当前编辑内容塞入旧键。
5. 409 不自动改版本再提交。暂停本单队列，重新读取服务器草稿、版本及绑定，展示差异并由用户确认合并；合并后的新写使用新键。401/403/404 同样停止队列并刷新身份或对象可见状态。

页面关闭重开时先恢复未决请求，确认其结果，再发送后续编辑。附件上传本身不递增申请版本；绑定/解绑在 TASK-06 接口实现后按同一队列处理，不能把上传成功当成绑定成功。

## 行键与附件合并

采购明细、报价、报销费用行在客户端创建时生成不重复 `clientKey`，同一草稿内跨集合唯一，最多 64 个 ASCII 字母、数字、下划线或短横线。行重排不换键，改内容不换键；不能把既有明细键改作报价键。键只关联草稿行，不是数据库正式行 ID。

保存为完整 payload 替换，不是局部 JSON patch。未填写的业务字段可以省略或保留允许的空字符串；出现的字段必须符合固定类型和精度，不接收 null、未知字段或伪造正式行 ID。采购最多 100 明细、10 报价，报销最多 50 费用行。本次仅检查草稿语法，不把未填完整的草稿当作可提交表单；合计、预算和提交完整性由 TASK-07/08 实现。

服务器响应中的 `bindings` 是本次事务确认的绑定快照。客户端按稳定行键合并，不按数组下标关联。删除行时，服务器在保存事务中解绑对应行附件，递增版本并登记清理候选；共享文件对象和其余绑定保留。前端不得因一行消失而自行删除共享文件。物理文件清理、预览、上传校验及中断恢复属于 TASK-06，本协议不宣称这些已可用。

流程任务、WAITING 阅读源及冻结正文由 TASK-09 集成。当前已提交申请只能返回基础元数据和 `bodyAvailable=false`，不伪造正式扩展正文或审批历史。
